# Warden progress critique — 2026-09-05

Baseline: `5aa73090fef0d3570a4c293f27c57c532bdc9f14`. Author review, not an
independent second-model review. This records findings about the local repository;
it does not re-score the prior independent security campaign or assess the live site.

## Findings

1. **The product is far behind the assurance infrastructure.** The shipped popup
   (`apps/extension/popup.html`, `src/popup/main.ts`) is a heading and an unavailable
   message. `apps/extension/scripts/build.mjs` explicitly excludes the provider,
   signing coordinator and RPC composition. The large test counts establish
   properties of components, not a working wallet. No onboarding, account creation,
   send flow or Wallet Standard registration exists in the shipped extension.
   The next milestone must be a usable local vertical slice, with explicit release
   boundaries; another release-verifier cycle alone will not close this gap.
2. **Approval delay measures the wrong interval.** `ApprovalArmGuard.armedAt()`
   uses focus time + 600 ms, but never review time + 600 ms. Focus at 0, a slow
   review at 5000, motion at 5001, down/up at 5002/5003 allows consent at 5004.
   The old helper even expects `reviewAt - 10 + DWELL`, encoding the mistake.
   A replacement review in the same focus run inherits the elapsed delay too.
   Shipped impact is limited because production cannot approve; fix before enabling it.
3. **Held keys can become consent.** `main.ts` forwards every Enter/Space keydown
   without `event.repeat`; the guard can replace a pre-arm keydown with its
   post-arm auto-repeat. A delay does not establish fresh consent in that case.
4. **The requesting origin can be visually concealed.** `.origin` uses
   `white-space: nowrap`, `overflow: hidden` and ellipsis. At narrow widths a long
   hostname can hide its distinguishing suffix. Full string DOM assertions cannot
   establish that the user can read it. Fix wrapping and measure rendered overflow.
5. **The review surface conflates evidence.** A green decoded-message status is
   shown alongside a policy version, without separate simulation/policy-check
   status. A version is not a policy verdict and decoding is not simulation.
   Show the limits explicitly; do not invent results.
6. **Progress documentation is internally inconsistent.** README calls Phase 1B
   in progress while describing it as complete, carries the obsolete 24/20 account
   caps, and SECURITY.md omits the extension from the reporting scope. These make
   progress harder to evaluate and can misdirect a vulnerability report.

## Selected local build slice

Fix the two consent timing defects without changing the pointer-presence policy
(O2 remains open). Preserve full origins and separate review evidence. Build a
useful development popup with capability/status guidance and a bounded,
retryable connection check. Update the concise project status and reporting scope.
Production signing, external trust values and deployment remain outside this slice.
