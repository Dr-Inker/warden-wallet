# Warden — security assurance with a second model, and what the Solana wallet landscape teaches

**Date:** 2026-08-18 · **Status:** decision document · **Inputs:** 20 research reports in `docs/research/raw-2026-08-18/` (cited `[R01]`–`[R20]`) and `critic.json` · **Checked against:** spec rev 7, the Phase 1B plan, `docs/spikes/DECISION.md`, `docs/program/PHASE1A-MEASUREMENTS.md`, and `programs/warden/src/` at `a02aaf0`.

**Read this first.** Six of the twenty reports analysed `execute`, the adapter registry and the conservation checks as if they were shipped code. They are not. `programs/warden/src/instructions/` contains exactly `create_account`, `freeze`, `unfreeze`, `grant_session`, `revoke_session`, `rotate_nonce`, `transfer` [R13, critic §contradictions]. Everything those reports say about `execute` is **design input for Phase 1B**, never an audit finding. Every claim below that touches code has been checked against the source.

---

## 0. TL;DR

1. **Add a forged-signature gate before proof-of-possession lands.** A live probe proved LiteSVM verifies secp256r1 for real, but **no shipped test uses a cryptographically invalid signature** — all 33 `root_verify` negatives are honestly signed [R16]. A dependency bump dropping the `precompiles` feature would silently leave `bind_precompile` as the only gate on the root of trust. It does not block bucket, spec or supply-chain work, but it must precede PoP.
2. **Highest-leverage process change: an ID-addressable invariant ledger** (`docs/security/INVARIANTS.md`) — today Codex reviews against nothing but the diff and its own judgement [R15, critic].
3. **Seed every review with the prior-art finding corpus** (ACC-C1/C2/H1/H2/M1/M2, TOB-SQUADS-7/8, ND-SQD3-LO-01, Swig ACC-C1/C2, Argent zero-guardian) — cheapest counter to shared LLM blind spots on Solana-specific classes [R12, critic].
4. **Codex output becomes typed JSON, not prose** — and **truth status is separated from evidence type**: `POTENTIAL / CONFIRMED / REFUTED` alongside `red_test | static_trace | formal_counterexample | config_attestation | primary_source`. A reproducer is required only where one is feasible; supply-chain, key-management, upgrade-authority and liveness findings are adjudicated by a human instead of auto-downgraded [R03, R15].
5. **Do not restructure the loop** to Claude-reviews-Codex on the cited +18.1/−8.6pp asymmetry — isolated Python tasks, and an executed pilot found real bugs *and* real false positives on both sides, the one FP caused by **reviewer scope, not model identity** [R19].
6. **Replay design is already best-in-class** — an O(1) scalar `root_nonce` with strict `n+1` equality, not the O(n) "consumed-nonce set" the spec implies. **But the freshness window is 10–25× wider than LazorKit's and Swig's** (600 s wall-clock vs 150/60 slots) and anchored to `unix_timestamp`, not `slot` [R18]. Tighten it.
7. **The conservation-check ambition is genuinely ahead of the field** — Squads v4 does *no* balance or state validation around CPI at all [R20]. Nobody runs before/after field-by-field diffing as the primary control, which makes it both the differentiator and an **unvalidated bet**.
8. **Four gaps in the unbuilt `execute` design:** no hard deny-list for `SetAuthority`/`Approve`/`CloseAccount`; Mint accounts absent from the snapshot set; **before/after snapshots cannot see a round trip that happens inside one CPI**, so net accounting has a semantic blind spot no snapshot design closes; non-WSOL rent lamports on `CloseAccount` are invisible to both outflow equations [R20].
9. **Token-2022 confidential mints break conservation outright** (ZK-hidden amounts) — a permanent non-goal, not an allow-listable extension [R14].
10. **Buckets are already epoch-floored UTC days with correct skipped-slot zeroing** (`buckets.rs`, verified) — [R05]'s "adopt Swig-style epoch-floor" is already satisfied and its rationale was asserted, not argued [critic]. No change.
11. **UV is mandatory in Warden and parsed-but-never-called in LazorKit** — a real instance of the exact slip [R04].
12. **Licensing bounds what "copy" means:** only LazorKit `program-v2` is MIT; Swig/Squads are AGPL-3.0 and Backpack GPL-3.0 — reference only. **Any reuse policy must be counsel-approved**; a copy-detection review prompt reduces risk but does not settle derivative-work law [R17].
13. **The biggest non-program risk is the release channel** — Trust Wallet lost $7–8.5M to a leaked Chrome Web Store publisher key, *likely* harvested by the Shai-Hulud npm worm (the vendor's own wording), inside all of Google's 2FA rules [R06]. Supply-chain work is therefore an assurance lane now, not a Phase-2 deferral.
14. **Never gate signing on a third-party simulator** — Blowfish silently missed an `assign` while Phantom displayed "Receive 1 SOL" [R10]. Reputation/blocklist feeds only, advisory.
15. **Provenance lesson:** [R14] asserted SIMD-0579/keccak-p1600 "does not exist"; controller re-check shows **PR #579 is OPEN** (predecessor #563 closed) but unmerged, which is why R14's `proposals/` search missed it. Both "live thread" and "fabricated" were half-right. Treat any protocol claim not backed by a source-pinned fetch or RPC call as suspect.

## 1. Assurance pipeline with Codex — the "watertight" plan

Ordered by dependency, not by importance. L0–L3 are prerequisites for the layers that consume them; they do not block bucket, spec or supply-chain work, which runs in parallel (L9).

**L0 — harness fidelity (must precede proof-of-possession).** *Proves the substrate actually enforces the cryptography.* `Cargo.toml:40` pins `litesvm = { version = "0.12", features = ["precompiles"] }` and `common::setup` calls `.with_mainnet_features()`; LiteSVM 0.12's `process_precompile` calls `agave-precompiles::…verify(...)` — real crypto, confirmed by live probe [R16]. But `precompiles` is not the default, `LiteSVM::default()` starts with every feature off, 0.13+ jumps to Agave 4.x, and nothing in the suite would notice a regression. **Changes:** `tests/sigverify_wiring.rs` gating on **both directions** — (valid signature ⇒ transaction succeeds) **and** (forged signature ⇒ exactly `InstructionError(0, Custom(2))`, `PrecompileError::InvalidSignature`). Only the pair proves the runtime is doing ECDSA; the "honest signature over a *different* message" case is a **binding** test for `bind_precompile`, not a crypto control, and belongs in `root_verify.rs`. **Pin exactly**: `Cargo.lock` currently resolves `litesvm 0.12.0`, so write `litesvm = { version = "=0.12.0", features = ["precompiles"] }` and keep the lock committed. `litesvm = "0.12"` already means `>=0.12,<0.13`, so the range I first proposed was a no-op, and `=0.12.x` is a wildcard, not a pin. `cargo tree -p litesvm -e features` is worth keeping in CI, but it proves *feature resolution*, not runtime verification; the two-direction test is the real gate. Add `.github/workflows/ci.yml` (none exists) running test-gate + clippy + both. **Cost:** under a day. **Dependency the reports missed:** [R03] wants PoC-backed findings, but until L0 lands there is no substrate on which to reproduce a passkey bug [critic].

**L1 — invariant ledger (`docs/security/INVARIANTS.md`).** *Proves nothing itself; makes every later layer addressable — "Codex ruled on WRD-EXEC-07", not "Codex reviewed it".* Precedent: Certora's Squads v4 report publishes named properties each with Verified/Violated status and a link to its machine-generated rule report [R15]. Same shape — **ID → statement → spec ref → code ref → prior art → proof status → evidence**; JSONL is the source of truth, the `.md` is generated:

```json
{"id":"WRD-EXEC-07",
 "statement":"No inner instruction of execute may set a delegate on a vault-owned token account.",
 "spec_ref":"…design.md#5.2 rule 3", "code_ref":"src/conservation/compare.rs:NN",
 "prior_art":["SWIG-ACC-C1","LZR-ACC-I2"],
 "status":"unimplemented|llm-asserted|test-covered|mutation-tested|proven|holds",
 "evidence":["tests/execute.rs::mutator_set_delegate_rejected"]}
```

`status` is the invariant's own standing, distinct from a *finding's* truth value (L2): **`holds`** means the invariant has at least one accepted evidence artefact of an allowed type and no open contradicting finding — it is the ledger-side counterpart of a `REFUTED` attack claim, and it is what L3 samples for false negatives. The remaining values are proof strength, ascending. Namespaces: `WRD-ROOT-*`, `WRD-CD-*`, `WRD-NONCE-*`, `WRD-SESS-*`, `WRD-CAP-*`, `WRD-EXEC-*`, `WRD-REG-*`, `WRD-STAGE-*`, plus `WRD-TL-*`/`WRD-GRD-*` for 1C and `WRD-BUF-*` — pre-seeded now from ND-SQD3-LO-01 *and* Certora H-01, two firms and two methods hitting the same unbounded-uncleanable-buffer-PDA bug, which is exactly `Stage`'s shape [R15].

**Seed `docs/security/PRIOR-ART-FINDINGS.md` in the same commit**, one entry per finding with its primary source and the Warden surface it maps to. Non-negotiable: **TOB-SQUADS-7** (unauthenticated `create_key` front-run) and **-8** (ephemeral signer seeds not per-transaction), [Trail of Bits Squads v4](https://github.com/Squads-Protocol/v4/blob/main/audits/trail_of_bits_squads_v4_security_audit.pdf); **ND-SQD3-LO-01** (buffer PDA seeds lacking the creator pubkey); LazorKit **ACC-C1** (accounts bound by *index, not pubkey*), **C2** (owner-role branch skipping "target belongs to this wallet"), **H1** (accounts omitted from the signed payload → rent theft), **H2** (write/read layout drift corrupting `rp_id_hash`), **M1** (truncated slot index wrapping), **M2** (no discriminator in the signed payload) — [Accretion A26SFR1](https://github.com/lazor-kit/program-v2), all fixed; **Swig ACC-C1/C2**; **Argent zero-guardian** ([OpenZeppelin](https://www.openzeppelin.com/news/argent-vulnerability-report)). **Cost:** ~1 day.

**L2 — per-task review, restructured.** *Proves a second model, seeded with the ledger, could not name a violated invariant it could reproduce.* Today (`CLAUDE.md`) every task is implemented by an isolated worker and adversarially reviewed by Codex `gpt-5.6-sol@max` in a fresh thread — already better than most. Five changes:

1. **Structured output** — `codex exec review --base <sha> --output-schema docs/security/finding.schema.json --ephemeral`, then validate the emitted JSON with an independent schema validator rather than trusting the flag. Three corrections to what the research asserted, checked locally against `codex-cli 0.147.0`: `--output-schema` constrains the **final response**, not every JSONL event, so a pipeline that greps intermediate events will mis-parse; profiles are loaded from `$CODEX_HOME/<name>.config.toml` (this host has `~/.codex/review.config.toml` and `deep-review.config.toml`), **not** a repo-local `.codex/profiles/*.toml`; and the "MCP servers silently disable `--output-schema`" claim [R03] is from an unofficial blog — **UNVERIFIED**, and it stays that way until a local 0.147 regression test reproduces it. Run the pass tool-free anyway, since that costs nothing and removes the variable.
2. **Separate truth from evidence.** `{invariant_id, truth: POTENTIAL|CONFIRMED|REFUTED, evidence_type: red_test|static_trace|formal_counterexample|config_attestation|primary_source, severity, file:line, prior_art_cited[], reproducer:{path,name,base_sha,fixed_sha}, confidence, notes}`. A **reproducer must FAIL on the vulnerable base SHA and PASS on the fixed SHA** — "fails on HEAD" is the wrong predicate once a fix lands. Require a test **only where one is feasible**: static traces, supply-chain and dependency-provenance findings, key-management and CWS-credential failures, upgrade-authority misconfiguration, economic/MEV and liveness attacks, and formal counterexamples are all real and mostly unreproducible as a LiteSVM test. Those route to **human security adjudication**, recorded in the scorecard with the reason — never auto-downgraded. The PoCo discipline [R03, R15] applies to the class it was designed for (exploitable program-logic bugs), not as a universal filter.
3. **Clean tree, always** — `codex review --base <sha>` on a dirty tree repeats *hallucinated* findings unrelated to the diff ([openai/codex#8404](https://github.com/openai/codex/issues/8404)); make it a precondition check.
4. **Fix reviewer scope, not model identity.** The pilot's one FP was Codex flagging `cluster_tag` binding in `create_account.rs` — a property `root_verify/transcript.rs:69-76` documents as knowingly deferred, in a file Codex wasn't shown [R19]. **Every round must name the sibling files carrying cross-cutting invariants** (`transcript.rs`, `state/session.rs`, `errors.rs`, `buckets.rs`) plus the ledger entries overlapping the diff. Silence on a seeded invariant is a FAIL.
5. **Blind and anti-rewrite** — diff + spec section + seeded invariants, no author framing, explicit instruction against rewriting working code (the 11.2% regression rate in the one cross-model study came from unnecessary rewrites). Standing checklist item for **dimensional/scaling bugs**: Moonwell shipped Claude-authored code using a cbETH/ETH ratio as if USD-denominated — 2,000× underpricing, $1.78M, human reviewer missed it [R03].

**L3 — scorecard (`docs/security/REVIEW-SCORECARD.jsonl`).** *Proves how often the reviewer is wrong — a question the current process structurally cannot answer.* Four Codex rounds on Phase 1A produced 1 Critical, 4 Important, 6 Minor, **100% adopted** — a survivorship artifact of what gets committed, not an FP rate of 0% [R19]. Log every finding, disputed and scoped-out ones included, with adjudication rationale; monthly, blind-re-review a 1-in-10 sample of invariants sitting at `holds` — those are where a false negative hides — weighting a missed bug worse than a false alarm. One regression is on record: the round-1 fix for the P-256 root check over-corrected and rejected `x = 0`, a valid point, caught by a *second* Codex round [R19, `4b409f7`]. **Rule: any diff that moves an accept/reject boundary gets a mandatory second-round confirm.**

**L4 — adversarial test generation and mutation testing.** *Proves the tests assert what they claim.*
- **`cargo-mutants` — pilot first, then gate.** [R01] says it works at the `cargo test` level with no Solana-specific integration; **that is unpiloted here** (`which cargo-mutants` returns nothing on this host, and SBF-target builds are exactly the kind of thing that breaks generic Rust tooling). Run a scoped pilot on `buckets.rs` before assigning it any proof status; if it holds, extend to `client_data.rs` grammar boundaries and later `conservation/compare.rs` and **gate CI on a mutation-score floor for those modules, not line coverage**. The same rule applies to every tool below: **no tool confers a ledger proof status until it has been piloted on this repo.**
- **Codex writes attack tests against mutants** — give it a `cargo-mutants` survivor plus the invariant statement; it must produce a test that **FAILS against the mutant and PASSES against the real program**, both checked mechanically. This is what makes generated tests trustworthy: LLM-authored properties score far below hand-written ones on mutation (25.99% vs 31.75%) unless mutation-guided [R03].
- **`proptest-state-machine` over a reference model** — a pure-Rust model of `SmartAccount`/`SessionKey`/bucket state, random sequences (grant/revoke, boundary transfers, day and 30-day rollovers, freeze/unfreeze, `execute` with CPI) replayed against LiteSVM with post-state equality asserted [R01]. Doubles as the near-spec that makes L6 affordable.
- **Trident fuzzing on two targets only** — `client_data.rs` and, in 1B, the `ExecutePayload` parser, the two places parsing attacker-controlled structure [R01]. Fuzzing is **bug-finding, not proof**: a clean campaign raises an invariant to `test-covered` at best, never to `proven`. Port LazorKit's regression vector verbatim, `{"tokenBinding":{"id":"x}y"},"challenge":"real"}`, where a `}` inside a nested string desynced their brace-depth tracker and mis-located `challenge` [R04]. Warden's depth-0 validator should reject it; prove it does.
- **Independent reimplementation → differential test** — the second-model use nobody proposed [critic]. Have Codex reimplement the clientDataJSON scanner and `buckets::debit` from the *spec text alone*, then differential-fuzz the pair; in the pilot, Codex-authored ring-buffer code had a real cap-weakening bug (closed day written to `ring[kept-1]` not `ring[RING_DAYS-1]`, permanently understating 30-day spend), caught first-pass by *running* it [R19]. **Cost:** mutation runs are compute-heavy — nightly, not per-commit, per this host's serialized-build rule.

**L5 — per-merge whole-feature review + weekly whole-repo sweep + threat-model diff.** *Proves cross-file interactions diff-scoped review cannot see — registry × conservation × buckets is exactly that shape.* **Every merge that completes a feature gets a whole-feature review**, not just its final diff: a weekly cadence lets a half-landed trust-surface change sit unreviewed for days. On top of that, a weekly whole-repo pass at `sol@xhigh`, cross-checked against an independent Claude sweep in a fresh thread. **Promotion rule (corrected): agreement is a confidence signal, not a filter.** Requiring both models to raise a finding compounds *correlated* false negatives — the shared-blind-spot failure the prior-art seeding exists to counter. So: a finding raised by either model enters the ledger as `POTENTIAL`. **Agreement between models is a confidence signal, not evidence, and never promotes on its own** — two models can be confidently wrong together, which is the whole reason for the prior-art seeding. `CONFIRMED` requires an evidence artefact of an allowed type (`red_test`, `static_trace`, `formal_counterexample`, `config_attestation`, `primary_source`) **or** an explicit human security adjudication; agreement only raises the finding's triage priority. **Disagreement escalates to a human and is never auto-dismissed**, with the ruling recorded. Per milestone, append to `docs/security/THREATMODEL.md` what changed in the trust surface — SHA-stamped, append-only, sign-off before merge.

**L6 — formal verification.** *Proves the specified model over all its reachable states — under the harness's assumptions.* A CVLR proof says nothing about runtime behaviour the model abstracts away: CPI effects, precompile semantics, account-loading, or the SBF the validator actually runs. State that limit next to any "proven" ledger entry. **Certora Solana Prover / CVLR** is the only production-credible option — Squads v4 was its first Solana engagement (2023, "no major security flaws"), and its init-establishes / every-method-preserves model matches Warden's account arithmetic [R01]. **Prove first, in order:** (1) **bucket conservation** — `spent_today == Σ` of the day's debits, `Σ(ring) ≤ per_30d`, no slot survives a rollover that should have zeroed it; (2) **cap dominance** — every accepted spend satisfies `amount ≤ min(per_tx, per_day − spent_today, per_30d − Σring)` and, for sessions, `lifetime_spent + amount ≤ lifetime_cap`; (3) **root-nonce monotonicity** — increases by exactly 1 per successful ceremony, never decreases, so no assertion is consumable twice; (4) after 1B, **`execute` conserves against a ghost ledger** — introduce ghost variables tracking authorised inflow and outflow per mint, and prove `Δbalance == ghost_in − ghost_out` with `ghost_out ≤ the cap that authorised it`. "Creates no value" is the wrong property: legitimate swaps and inflows raise vault balances by design, so a monotone no-increase rule would be false on the happy path. Do this **after** L4's reference model stabilises — it is nearly a spec-in-Rust and sharply lowers CVLR cost. **Caveat:** "public repo likely qualifies for Certora's free OSS tier" is sourced to a CVL rules doc, not a pricing page [critic]; get a written quote, and budget ~5 weeks. **Kani: watch-list, not adopt** — OtterSec's `anchor-lang` prototype is a Jan-2023 effort with path explosion and "CPI verification difficult if not impossible" [R01], yet OtterSec *did* use Kani productively in the 2024 Squads audit to prove concrete invariants (≥1 proposer/executor/voter, no duplicate members, `threshold > 0`, `remaining_amount ≤ amount`, non-malleability, signer-seed uniqueness) [R12]. Ask the audit firm to bring it. **SseRex** is a paper with no packaged CLI.

**L7 — pre-deploy recon, audit, bounty, build integrity.** Adopt LazorKit's audit-prep artifacts wholesale [R09, R12]: tag `audit-frozen-v1`; record the SBF SHA-256 and `solana-verify get-program-hash`; a CI gate that `git grep`s for `TODO`/`unimplemented!`/`#[ignore]` on the audit branch; `DELTA_BRIEF.md` + `upstream-parity.txt` so re-audits scope to the true delta. Use `solana-verify` as a **release gate**, not assurance — Accretion published a defeat of the pipeline [R01]. Every unproven HIGH-severity ledger entry gets an attempted exploit against a LiteSVM/localnet fork before go/no-go [R03], and L9's deployment gate runs at the same point. External audit + public bounty before real funds (spec §10/§11); Squads' tiering is the reference shape (theft $300k, fund-freezing $200k, replay $25k, config change $10k) [R05]. **Improve on-chain logging** — Trail of Bits rated Squads' "not sufficient for off-chain monitoring to detect an ongoing attack" [R12]; emit structured events on every bucket debit, cap rejection, freeze and (1C) timelock trigger, since the notifier is the second channel that makes threat T3 survivable.

**L8 — the A/B that decides review-loop shape.** Matched pairs across ~10–15 Phase-1B sub-tasks: each scope reviewed by Claude, by Codex, and by both, blind, scored by a fixed third adjudicator. `execute`, the registry and the payload parser have ample function-scale surface [R19]. Until it returns, the loop stays as it is.

**L9 — the lanes "watertight" actually requires.** L0–L8 harden the on-chain program, which is not where most wallet users lose money. Each lane below needs an executable gate, and they run **in parallel with 1B, not after it** — the Trust Wallet finding makes the supply-chain lane urgent now, not a Phase-2 item.

## 2. Landscape — adopt, avoid, and where Warden is already ahead

Licences bound what "copy" can mean. **LazorKit `program-v2` = MIT** (`LICENSE` file). **Squads v4 and `smart-account-program` = AGPL-3.0** (`LICENSE`); **Backpack = GPL-3.0** (`LICENSE`); **Swig = AGPL-3.0 stated in its README, with no root `LICENSE` file** — GitHub's detector returns null, which is itself a diligence item [R17]. Copyleft attaches to the *combined work* and shipping an extension triggers GPL §5; AGPL §13's network clause over on-chain execution is legally untested. **This document does not settle that.** The operative rule is procedural: **any reuse of non-MIT prior art requires a counsel-approved reuse policy before code lands**, and "we reimplemented it clean-room" is a claim counsel evaluates, not a conclusion an engineer or a review prompt can reach. A standing review-prompt item — *"does this diff reproduce structure, naming or comments recognisably from Swig/Squads/Backpack?"* — reduces exposure to substantial-similarity claims but does not settle derivative-work law. Don't reuse names or marks either way.
