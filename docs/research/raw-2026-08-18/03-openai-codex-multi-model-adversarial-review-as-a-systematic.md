# OpenAI Codex + Multi-Model Adversarial Review as a Systematic Security Process — Report for Warden Wallet

## Findings

**Codex CLI mechanics (2026, v0.147.0 stable, Aug 7 2026)**
- `codex review --base <sha>` / `codex exec --profile <name> --output-schema <schema.json>` produce diff-scoped or whole-repo reviews with machine-parseable JSON findings, enabling ledger ingestion instead of prose. [openai-codex-plugin-cc.mintlify.app/commands/review](https://openai-codex-plugin-cc.mintlify.app/commands/review), [codex.danielvaughan.com/2026/05/15](https://codex.danielvaughan.com/2026/05/15/codex-sdk-custom-code-review-pipelines-structured-findings-github-gitlab-azure/)
- **Gotcha**: `--output-schema` is silently ignored whenever MCP servers/tools are active in the session — schema-constrained review must run as a separate, tool-free pass after any MCP-context-gathering pass. [codex.danielvaughan.com/2026/05/01](https://codex.danielvaughan.com/2026/05/01/codex-cli-production-log-analysis-root-cause-mcp-pipelines/)
- **Known bug**: `codex review --base` against a dirty working tree repeats *hallucinated* findings that don't correspond to the actual diff — base-scoping alone doesn't guarantee grounded findings. [github.com/openai/codex/issues/8404](https://github.com/openai/codex/issues/8404)
- Sandbox (`read-only`/`workspace-write`/`danger-full-access`) + approval policy (`untrusted`/`on-request`/`on-failure`/`never`) + `auto_review` reviewer-agent gate are the security model; `AGENTS.md` is the persistent-instruction equivalent of CLAUDE.md. [developers.openai.com/codex/agent-approvals-security](https://learn.chatgpt.com/docs/agent-approvals-security), [github.com/openai/codex/blob/main/docs/sandbox.md](https://github.com/openai/codex/blob/main/docs/sandbox.md)
- Warden's own verified sandbox testing (this host, 2026-08-17) found the sandbox is **not** a trustworthy sole boundary: Codex's built-in "known-safe" allowlist runs `echo`/`printf` outside the sandbox and ignores `>` redirection, and bare-prefix rule allows (`bash`, `curl -fsSL`) nullify the write-scope profile entirely — `/opt/docs/CODEX-USAGE-DOCTRINE.md` §3. This generalizes: never treat any single model or sandbox as the security boundary; use independent verifiers.

**Multi-model adversarial review — what the research actually shows**
- Cross-model review is **asymmetric**, not simply additive: on 116 post-cutoff LiveCodeBench tasks, Claude reviewing Codex's code lifted pass rate 71.6%→89.7% (+18.1pp) with 4.3% regression rate; Codex reviewing Claude's code *dropped* it 91.4%→82.8% (−8.6pp) with 11.2% regression, driven by unnecessary rewrites of working solutions. [arxiv.org/html/2607.21656v1](https://arxiv.org/html/2607.21656v1) — **caveat**: isolated Python problems, not repo-scale/multi-file, explicitly flagged by the authors as out of scope; Warden's current pairing (Claude implements, Codex-only reviews) is the *weaker* direction per this single study — UNVERIFIED for Rust/Anchor at repo scale.
- Same-model self-review exhibits a "self-correction blind spot": models fail to catch errors in their own output that they catch when the identical error is presented as external input, averaging 64.5% blind-spot rate across 14 models — the core argument for never letting a model review its own generation. [nhimg.org](https://nhimg.org/articles/cross-model-ai-code-review-exposes-the-limits-of-single-model-judgment/), [arxiv.org/html/2603.12123](https://arxiv.org/html/2603.12123) (cross-context/blinded review as mitigation)
- Ensemble/self-consistency across independently-trained models: LLMBugScanner's 5-model weighted-vote ensemble beat single-model baselines by ~19pp (top-5 accuracy ~60%) but ~10% of *all* model outputs across the study were invented/unsupported vulnerabilities — ensembling reduces noise, doesn't eliminate hallucination. [helpnetsecurity.com/2025/12/19](https://www.helpnetsecurity.com/2025/12/19/llmbugscanner-llm-smart-contract-auditing/)
- **Evidence-bound review**: PoCo treats a vulnerability as confirmed only if the LLM agent can construct a working, executing exploit against it; static-tool findings without a runnable PoC are discarded/deprioritized — this is the strongest available mitigation for hallucination. [arxiv.org/pdf/2511.02780](https://arxiv.org/pdf/2511.02780)
- **Invariant extraction**: PropertyGPT/SpecGen/DbC-GPT show LLMs can retrieve/generate formal-ish invariants (pre/post-conditions) from spec+code, useful as a *checklist generator*, not a verifier. [NDSS PropertyGPT](https://www.ndss-symposium.org/ndss-paper/propertygpt-llm-driven-formal-verification-of-smart-contracts-through-retrieval-augmented-property-generation/)
- **Mutation-checked tests**: LLM-generated Solidity properties reach mutation scores far below hand-written ones (best config 25.99% vs. human 31.75%), meaning LLM-authored tests must be mutation-scored before being trusted as "proof," not accepted on generation alone. [arxiv.org/html/2607.23308](https://arxiv.org/html/2607.23308); general mutation-guided LLM test generation (MUTGEN) shows the technique closes this gap dramatically when applied. [arxiv.org/abs/2506.02954](https://arxiv.org/abs/2506.02954)
- **CHAINTRIX**'s multi-pipeline pattern — invariant extraction → systemic attack-path analysis → adversarial red-team verification — is close to the exact 3-stage shape this task asks Warden to build. [researchgate.net/publication/404752769](https://www.researchgate.net/publication/404752769_CHAINTRIX_A_multi-pipeline_LLM-augmented_framework_for_automated_smart-contract_security_auditing)
- **Anthropic Frontier Red Team, SCONE-bench**: 10 frontier models collectively exploited 51.11% of 405 real historical vulnerable contracts ($550.1M simulated); on post-cutoff contracts, Opus 4.5/Sonnet 4.5/GPT-5 hit 55.8% ($4.6M); a zero-day scan of 2,849 fresh BSC contracts cost $1.22/contract, $1,738 per confirmed-vulnerable contract, and found 2 real zero-days. Exploit revenue roughly doubled every 1.3 months over the prior year. Authors explicitly recommend using the *same* agentic exploit-generation capability defensively, pre-deployment. [anthropic.com/research/smart-contracts](https://www.anthropic.com/research/smart-contracts)
- **Cautionary case**: Moonwell shipped Claude Opus 4.6-authored code with a cbETH/USD unit-conversion bug (used the cbETH/ETH ratio as if already USD-denominated → 2,000x underpricing), causing a $1.78M loss; a human "reviewed" it and missed it — proof that LLM-assisted review does not automatically catch dimensional/scaling bugs, exactly the class Warden's `execute` before/after conservation checks are meant to guard against. [cryptopolitan.com](https://www.cryptopolitan.com/claude-moonwell-smart-contract-exploit/)

## What Warden should adopt / change

1. **Per-task review**: Keep Codex-per-task, but (a) force fresh threads (already Warden doctrine), (b) run a schema-only pass (`--output-schema`, no MCP tools active) so every finding lands as typed JSON — `{invariant_id, file:line, severity, evidence: {repro_test|poc|none}, confidence}` — appended to a ledger, not prose; (c) blind the reviewer to task framing/author, feeding only diff + relevant spec section, to blunt sycophancy; (d) instruct explicitly against unnecessary rewrites (mirrors the 11.2%-regression failure mode) — prefer minimal targeted fixes.
2. **Add a second, structurally different reviewer at milestone/pre-deploy gates**: a fresh-thread Claude-Opus pass over Codex-authored or Codex-reviewed diffs, since the one available benchmark suggests Claude→Codex review outperforms Codex→Claude review — but run Warden's own controlled A/B on real Anchor/TS diffs before trusting this cross-domain (their own doctrine already owes a terra@high vs sol@xhigh comparison; extend it to include a Claude-reviews-Codex leg).
3. **Per-milestone threat-model diff**: maintain `THREATMODEL.md` (trust boundaries: passkey verify, secp256r1 precompile + Instructions-sysvar introspection, session-key caps/buckets, timelock, adapter registry, execute conservation checks). At each milestone, run one deep-review model against "what changed in the trust surface since last entry," append-only, SHA-stamped, sign-off required before merge to main.
4. **Weekly whole-repo adversarial sweep** (cron via `CronCreate`, `sol@xhigh`, tool-free schema pass): whole-repo, not diff-scoped, specifically to catch cross-file/adapter-registry interactions single-diff review structurally can't see. Cross-check with an independently-run Claude sweep in a fresh thread; only findings both models raise, or that ship with a reproducing test, promote to the ledger — singleton claims go to a "candidates" bucket for human/PoC triage. This directly targets both the ~10% hallucination rate and the #8404 stale-base repetition bug.
5. **Pre-deploy recon**: upgrade the existing recon step to require PoCo-style exploit attempts (LiteSVM/localnet fork) against every unproven HIGH-severity invariant-ledger entry before go/no-go; adopt SCONE-bench's harness pattern for the fork-and-attack loop.
6. **Invariant ledger with proof status**: `INVARIANTS.md`/`invariants.jsonl`, one row per protocol invariant (nonce single-use, session-key cumulative ≤ cap, day/30-day bucket reset correctness, execute() before/after conservation, WebAuthn clientDataJSON challenge binding), status enum `{unverified, llm-asserted, test-covered, mutation-tested}`. Seed via LLM property-extraction (PropertyGPT-style) against spec+code; promote to `test-covered` only after mutation-testing (MUTGEN/PRIMG-style) confirms the covering test actually kills injected mutants of that logic — do not accept LLM-generated test presence alone as proof.
7. **Domain-specific checklist for dimensional/scaling bugs** in every review pass (Moonwell-class), tying into the `dimensional-analysis` skill already available — this failure class is structurally invisible to free-form LLM review and needs an explicit prompt/checklist item.
