# Solana Wallet Landscape: Open Source, Security Architecture, Incidents & Parity Gaps

## Findings

**Open source status — mostly partial/closed for the majors**
- **Phantom**: core wallet (key derivation, signing) is closed/proprietary. Walletbeat rates it FAIL on FOSS: "does not allow the user to freely audit, modify, and redistribute" ([walletbeat.eth.limo/phantom](https://beta.walletbeat.eth.limo/phantom/)). Phantom does publish auxiliary pieces: a community-maintained domain blocklist (2,000+ entries, updated daily, PhishFort partnership, 1,000+ takedowns) and dev SDKs ([phantom.com/learn/blog/security-at-phantom](https://phantom.com/learn/blog/security-at-phantom)).
- **Solflare**: same pattern — GitHub org (`solflare-wallet`) publishes 38-40 repos but **only SDKs/libraries/utilities** (solflare-sdk, blocklist, token-list, Flutter plugins, deep-link sample app). The actual extension/mobile wallet app source is **not published** ([github.com/orgs/solflare-wallet/repositories](https://github.com/orgs/solflare-wallet/repositories)).
- **Glow**: marketed as open-source and Solana-only, with local key storage + biometrics and pre-broadcast simulation of every transaction ([cryptoadventure.com Glow review 2026](https://cryptoadventure.com/glow-wallet-review-2026-solana-simplicity-anti-spam-design-and-who-it-fits-best/); [academy.swissborg.com/glow-wallet](https://academy.swissborg.com/en/learn/glow-wallet)) — UNVERIFIED against actual repo (could not locate/audit the primary GitHub org in this pass).
- **Jupiter Mobile**: closed-source wallet app; only the **Jupiter Wallet Kit** (adapter/UI toolkit) is open source ([developers.jup.ag/docs/tool-kits/wallet-kit](https://developers.jup.ag/docs/tool-kits/wallet-kit)).
- **Solana Mobile Seed Vault**: the **client SDK/AIDL interface** is open source, Apache-2.0 ([github.com/solana-mobile/seed-vault-sdk](https://github.com/solana-mobile/seed-vault-sdk)). Design principle: secrets are moved into the device's highest-privileged secure execution environment (secure processor mode / auxiliary coprocessor) and never leave it ([docs.solanamobile.com/developers/seed-vault](https://docs.solanamobile.com/developers/seed-vault)). **The actual on-device system-service implementation running on Saga/Seeker is not documented as open source anywhere found** — only the interface/SDK is public. Treat as closed/UNVERIFIED.
- **Ledger app-solana**: genuinely open source, Apache-2.0, at `github.com/LedgerHQ/app-solana` (fork of `solana-labs/ledger-app-solana`) ([github.com/LedgerHQ/app-solana](https://github.com/LedgerHQ/app-solana)). No audit report/Donjon review is linked from the repo itself in this pass — Ledger's secure-display hardware is CC EAL6+/ANSSI certified at the *device* level, but that doesn't equal an app-specific published audit ([ledger.com/academy — clear signing](https://www.ledger.com/academy/topics/ledgersolutions/ledger-live-clear-signing-the-safest-way-to-approve-crypto-transactions)).
- **wallet-adapter / wallet-standard**: fully open source under Anza (`anza-xyz/wallet-adapter`, `anza-xyz/wallet-standard`) and is the de facto connect-flow interop layer nearly every wallet implements ([anza-xyz.github.io/wallet-adapter](https://anza-xyz.github.io/wallet-adapter/)).

**Disclosed audits**
- Phantom: **Least Authority** (final report 7 Jun 2024, PDF) scoped to browser-extension key derivation/password storage/encryption/HD-wallet logic and deep-link handling (Open Redirect / XSS in WebViews) — best-effort extraction flagged a PBKDF2 iteration-count concern; treat specifics as **UNVERIFIED** pending a clean re-read of the PDF ([leastauthority.com PDF](https://leastauthority.com/wp-content/uploads/2024/07/Least-Authority-Phantom-Wallet-Final-Audit-Report.pdf)). Phantom is also stated to be audited by **Kudelski Security**, but no public scope/report was locatable in this pass — **UNVERIFIED**. Phantom runs a bug bounty up to $50k ([cryptoslate.com Phantom review](https://cryptoslate.com/crypto-wallets/phantom-wallet-review/)).
- Solflare, Glow, Jupiter Mobile: no disclosed third-party audit reports located in this pass — **UNVERIFIED / possibly nonexistent publicly**.

**Incident history**
- **Slope, Aug 2022**: Slope's mobile app transmitted plaintext/unencrypted seed phrases to a centralized logging/monitoring server; ~8,000-9,231 wallets drained, ~$4.1-8M stolen over ~4 hours. Notably ~60% of victims were **Phantom users** who had at some point imported their seed into Slope — the leak was Slope's, not Phantom's or Solana's cryptography ([solana.com/news/8-2-2022-application-wallet-incident](https://solana.com/news/8-2-2022-application-wallet-incident); [theblock.co](https://www.theblock.co/post/161425/slope-wallet-provider-saved-user-seed-phrases-in-plain-text-solana-security-researchers-find)).
- **Blowfish "assign"-instruction bypass (Coinspect research)**: Blowfish's Solana simulation failed to flag the `assign` instruction (ownership transfer) hidden alongside a benign-looking `transfer`; Phantom (relying on Blowfish) showed users "Receive 1 SOL" while silently reassigning account ownership to an attacker program, enabling later drains. Malicious contracts can also detect the simulated environment and behave differently live vs. in simulation. Phantom patched within two days of disclosure ([coinspect.com/blog/transaction-simulation-challenges](https://www.coinspect.com/blog/transaction-simulation-challenges/)). This is a **direct, load-bearing lesson for Warden's own preview/simulation layer**.
- **Murphy v. Phantom Technologies / OKX (filed ~Apr 2025)**: alleges Phantom kept decrypted private keys resident in browser working memory during active sessions; attacker who compromised the plaintiff's PC (Jan 20 2025) exfiltrated the key from memory and used Phantom's built-in Swapper to liquidate ~$500k of a token for $37.5k SOL, collapsing its market cap; suit seeks $3.1M ([cryptobriefing.com](https://cryptobriefing.com/phantom-security-breach-lawsuit/), complaint PDF via [business.cch.com](https://business.cch.com/srd/20250416_SRD_Murphy-v-PhantomTechnologies_complaint.pdf)). Allegation, not adjudicated fact — mark **UNVERIFIED/disputed**.
- **A ~$1.5M / 80-victim "blind signing" Phantom incident, May 2025**: repeated across secondary sources but no primary post-mortem located — **UNVERIFIED, low confidence**.
- **FoxyWallet campaign, discovered Jul 2025**: 40+ malicious Firefox extensions impersonating Phantom, MetaMask, Trust Wallet, Coinbase Wallet, Exodus, OKX, Keplr etc.; attackers cloned open-source wallet codebases and inserted drainer logic, active since ≥Apr 2025 ([thehackernews.com](https://thehackernews.com/2025/07/over-40-malicious-firefox-extensions.html), [koi.ai FoxyWallet](https://www.koi.ai/blog/foxywallet-40-malicious-firefox-extensions-exposed)). Earlier, a wave of ~150 crypto-draining extensions hit the Firefox store ([bleepingcomputer.com](https://www.bleepingcomputer.com/news/security/wave-of-150-crypto-draining-extensions-hits-firefox-add-on-store/)).
- Industry scale: Scam Sniffer's 2024 report puts wallet-drainer losses at $494M (+67% YoY) across 332,000+ addresses.

**Feature parity signals**: SIWS (Sign In With Solana) is a Wallet Standard first-class feature natively supported in `wallet-adapter`, Phantom (since v23.11), Solflare, Backpack ([phantom.com/learn/developers/sign-in-with-solana](https://phantom.com/learn/developers/sign-in-with-solana)). Versioned transactions + ALTs are Phantom-documented and adapter-standard ([docs.phantom.com/developer-powertools/solana-versioned-transactions](https://docs.phantom.com/developer-powertools/solana-versioned-transactions)). Priority-fee UI (low/medium/high/custom) is table-stakes in both Phantom and Solflare. Spam handling: Phantom uses ML + SimpleHash to auto-hide spam NFTs/tokens, a user "report as spam" flow, and a burn-for-rent-recovery function (600k+ NFTs burned).

## What Warden should adopt / change

1. **Don't trust a single third-party simulator as ground truth.** The Coinspect `assign`-instruction bypass shows Blowfish-class simulation can miss ownership-transfer instructions entirely while showing a friendly "receive" preview. Warden's before/after conservation-check + adapter registry design is structurally *better* than pure simulation-diffing (it constrains at the program/discriminator level rather than trusting a simulated trace) — keep pushing on-chain enforcement primary, treat any off-chain preview as advisory only, and explicitly test for ownership/authority-change instructions hidden inside otherwise-benign-looking bundles.
2. **Never hold decrypted secrets in long-lived browser memory** — the Murphy v. Phantom allegation, credible or not, is exactly the failure mode Warden's P-256-passkey + on-chain PDA root design structurally avoids (no extension-resident master key to steal); make sure session keys are similarly scoped (short TTL, capped) and never cached decrypted beyond the signing operation.
3. **Match, don't skip, the connect/auth layer**: implement SIWS via the Wallet Standard so dApps get it for free through `wallet-adapter` — this is now baseline expectation, not differentiation.
4. **Ship first-class ALT + versioned-tx support** and a priority-fee UI (low/med/high/custom, ideally with a live percentile estimator) — currently table-stakes across Phantom/Solflare.
5. **Publish a blocklist and spam-token/NFT triage UX** (report → hide → burn-for-rent) — cheap to build, high perceived-safety value, and Phantom's is itself open source/community-maintained, so Warden could fork/subscribe rather than build from scratch.
6. **Match Ledger passthrough support explicitly and go further on clear-signing**: Ledger's Solana app is open source (Apache-2.0) but historically Solana instruction decoding on-device has lagged EVM's clear-signing/CSA work (industry chatter suggests SOL support still leans on blind signing for many program types — **UNVERIFIED**, needs re-check). Warden's own before/after conservation display at the extension layer should compensate for this gap explicitly when a hardware signer is attached.
7. **Publish disclosed audits with explicit scope**, the way Least Authority's Phantom report is public — Warden's two-model (Claude/Codex) loop is good internal QA but is not a substitute for a named external audit firm's report once funds are real; get one commissioned and link it publicly, matching Phantom's posture even though Phantom itself stays closed-source otherwise.
8. **Actively monitor for clone-drainer extensions** (FoxyWallet pattern: attackers fork open-source wallet code, inject drainer logic, republish to extension stores) — since Warden is open source, this is a direct, near-certain threat vector; register/monitor trademark+store listings and consider store-side integrity signing.

Medium overall.
